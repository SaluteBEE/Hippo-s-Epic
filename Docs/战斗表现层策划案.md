## 一、现状与目标

### 1.1 当前状态（2026-08-06 实测）

战斗**逻辑层**已相当完整（约 5200 行）：

- ✅ 回合队列 / 速度排序 / 阶段机（RoundStart→TurnQueue→RoundEnd）
- ✅ 技能 v2：公式伤害、九宫格目标解析（行/列/全体/自身）、冷却、BuffOnly 分支
- ✅ Buff 系统（永久/次数/持续回合、存档序列化）
- ✅ 胜负判定 + OnBattleEnd 事件链
- ✅ 敌方 AI（血量判断/治疗/选目标）
- ✅ 战斗场景 + 角色生成 + 血条（BattleStageManager 567行）

但**表现层几乎是空的**（用户反馈：选中角色执行等表现都没有）：

| 缺失项 | 现状 | 影响 |
|---|---|---|
| 选中角色反馈 | 仅一个三角形 TargetSelectionIndicator | 不知道"选的是谁" |
| 技能目标范围提示 | 无 | 九宫格技能看不出作用范围 |
| 攻击演出 | 点技能→数字直接结算 | 没有"出招→命中→反馈"的节奏感 |
| 受击表现 | 无 | 被打毫无反应 |
| 伤害飘字 | 无 | 伤害无存在感 |
| 技能特效 | 无 | 技能全是"纯逻辑" |
| 演出时序 | 无（秒结算） | 回合制没有"戏" |
| 对话/喊话演出 | TODO（BattleWindow.cs:333） | 角色不说话（【暂缓】本期不做） |
| 物品使用 | TODO（BattleWindow.cs:342） | 物品 UI 没接 |

### 1.2 目标

以"演出化回合制"为标杆，为 Hippo 建立一套**可扩展、不侵入逻辑层**的战斗表现层：

1. 所有表现走**演出队列**，一次行动 = 一段完整的"戏"（移动→出招→命中→反馈→下一位）
2. 选中/目标/范围有清晰视觉反馈（这是用户点名要的）
3. 特效与动画走配表驱动（Luban 加字段），策划可配，不写死
4. 逻辑层（BattleManager）只发"结果"，表现层负责"怎么演"

## 二、演出化回合制架构拆解（通用模式）

### 2.1 三大核心

**① Sequence（演出序列）** — 930 行基类，一切行动的"剧本"

```
Sequence
├── StartSequence(targets)   ← 开始
├── SequenceStartBranch()    ← 开场（移动、转身、说话）
├── SequenceMainBranch()     ← 主体（攻击动画、等待 ActionCommand 输入）
├── SequenceSuccessBranch()  ← 命中（伤害结算、特效）
├── SequenceFailedBranch()   ← 失败
├── SequenceMissBranch()     ← 未命中
├── SequenceEndBranch()      ← 收尾（归位、清理）
└── EndSequence()
```

每个技能 = 一个 Sequence 子类（Mario 的 Jump/Hammer、每个伙伴、每个敌人都有专属 Sequence）。**演出被拆成分支阶段，每个阶段可以插动画、等待、播特效、发消息**——这就是"回合制有戏"的核心。

**② BattleEventManager（事件队列）** — 带优先级的演出事件系统

```
QueueBattleEvent(priority, battleState, event)
├── DamagedBattleEvent   ← 受击动画（等动画播完才算 Done）
├── DeathBattleEvent     ← 死亡演出
├── MessageBattleEvent   ← 战斗喊话（默认等 2000ms）
├── MoveToBattleEvent    ← 位移（带残影 MoveWithAfterImages）
├── PlayAnimBattleEvent  ← 播指定动画
├── HealHPBattleEvent / HealFPBattleEvent ← 治疗演出
└── ...
```

**关键规则：事件接管实体，必须完成才能轮到下一个实体**。所有演出串行不重叠，节奏可控。优先级机制保证"死亡演出"永远插队。

**③ ActionCommand（行动指令 QTE）** — 回合制经典的输入演出

```
JumpCommand / HammerCommand / GuardCommand / MashButtonCommand / FillBarCommand ...
```

攻击命中时弹出小游戏（按时机/连打/蓄力条），按得好伤害加成。**这是"玩家参与演出"的关键设计**——把"点技能等结果"变成"点技能→秀操作→看演出"。

### 2.2 辅助系统

| 系统 | 作用 |
|---|---|
| BattleObject（HPBarManagerObj / EntityListenerObj） | 血条跟随实体、受击自动显示/隐藏 |
| ObjAnimManager / Animation | 统一动画播放管理（Loop/Reverse） |
| BattleUIManager | 菜单 Suppress/Unsuppress（演出时禁菜单） |
| Interfaces（IActionCommandHandler） | 输入与逻辑解耦 |

### 2.3 对 Hippo 的启示（一句话版）

> **给"逻辑结果"包一层"演出剧本"：一次行动 = Sequence 分支演出 + 事件队列串行 + 可选 QTE 互动 + 血条/飘字/特效反馈。逻辑层只管算，表现层只管演。**

## 三、Hippo 表现层设计方案

### 3.1 总体架构

```
BattleManager（逻辑，不动）
    │  触发事件（OnSkillExecuted / OnDamaged / OnBuffApplied / OnBattleEnd ...）
    ▼
BattlePresenter（新增，表现层总控）
    ├── ActionSequenceRunner  ← 演出序列执行器（P0 核心）
    │       每个行动 = 一个 Sequence（数据驱动，不写死类）
    ├── BattleEventQueue     ← 演出事件队列（优先级，串行）
    ├── TargetFeedback       ← 选中/目标/范围反馈
    ├── DamageFx             ← 伤害飘字/血条动画/闪白/震屏
    ├── SkillFxManager       ← 技能特效（Addressables 加载）
    ├── DialogueBubble       ← 战斗喊话（接上 BattleTalkPanel）【暂缓，本期不实现】
    └── BattleHudEnhancer    ← HUD 增强（行动者高亮、回合提示）
```

**接入点**（现有代码已具备）：
- BattleManager 已有 `OnBattleEnd`、`OnBuffApplied` 等事件 → 表现层订阅即可
- BattleStageManager 已有单位 GameObject / 血条 / 高亮方法 → 直接扩展
- 新增事件：`OnSkillExecuted(actor, skillId, targets, results)`、`OnUnitDamaged(unit, dmg)`、`OnUnitTurnStart(unit)` —— 在 BattleManager 现有调用点加 3-4 行 Invoke

### 3.2 动态选择系统（P0，重写——参考憎恶之西的选择交互）

> 憎恶之西的选择交互核心：**键盘/手柄驱动的高亮游标 + 即时目标反馈**，选择本身就有"手感"。
> Hippo 九宫格战斗在此基础上做"格子游标"版本（战斗 UI 布局已够用，缺的是动态选择逻辑）。

**设计原则：任何一步操作都有 3 层反馈——可做什么 / 选了什么 / 结果如何**

#### 3.2.1 输入方式（键鼠 + 手柄全支持）

| 输入 | 功能 |
|---|---|
| 方向键 / WASD / 手柄左摇杆 | 目标游标在九宫格移动（每次一格） |
| 鼠标悬停 | 游标瞬移跟随（悬停即预览） |
| 鼠标左键 / 手柄A / 回车 | 确认当前目标 |
| 手柄B / Esc / 右键 | 取消，返回上一级菜单 |

#### 3.2.2 目标游标（TargetCursor）

- 九宫格上有一个**高亮游标格**（白色半透明框 + 四角箭头），初始位置 = 默认目标所在格
- 移动：每按一次方向键移动一格，游标带 0.05s 平滑过渡（Lerp），**不能移出九宫格边界**
- 游标停留的格上无单位时：显示半透明空框（提示"这格没人"）
- 游标位置与 `BattleManager.GetSkillTargets()` 实时联动——移动时立刻重算当前可命中目标

#### 3.2.3 目标三态显示（同一时刻只会出现一种）

| 状态 | 显示 | 触发 |
|---|---|---|
| 可行目标 | 脚下红/绿箭头（敌人红、友方绿）+ 头顶↑提示 | `CanSelectSkillSlot` + `GetSkillTargets` 非空 |
| 不可行目标 | 整体半透明 50%（仍可看到） | 存活但不可选 |
| 悬停目标 | 白色发光描边 + 头顶名字条 | 游标所在格有可行目标 |

#### 3.2.4 锁定与取消

- 确认：目标头顶 "!" 闪烁 0.3s（2 次）→ 锁定 → `PlayerUseSkill` → 进入演出
- 取消：返回技能面板（保留已选技能），再取消回行动菜单
- 技能 targettype=Self：无需选目标，直接确认释放

#### 3.2.5 技能范围预览（SkillRangePreview）

- 技能面板悬停/聚焦技能 → 九宫格覆盖层（半透明网格 UI，复用站位点/指示器思路）
- 显示规则（对应 skill 表 range + targettype）：
  - 可攻击格：红框（伤害技能）
  - 可治疗格：绿框（治疗技能）
  - 行/列/全体技能：整排/整列高亮
  - 当前游标格：白框覆盖红/绿
- 数据源直接调 `SkillCombatUtil.ExpandRangeSlots(游标格, range)` —— 逻辑层已具备，表现层只画

#### 3.2.6 敌人出招预告（Telegraphing，P1，憎恶之西核心喜剧点）

- 敌人行动前 0.5s 显示"预备"状态：
  - 头顶弹出出招文字（"野猪即将冲锋！"）+ 出招图标
  - 脚下预警圈（红圈缓慢收缩）
- 玩家在预告期可决定：防御 / 逃跑 / 提前打断（P2 扩展）
- 作用：把"敌人打你"变成"你知道敌人要打你"——策略 + 喜剧双收

### 3.3 伤害/受击反馈（P0）

| 事件 | 表现 |
|---|---|
| 命中 | 受击者：闪白(0.1s) + Spine 受击动画 + 位移后仰 0.1s |
| 伤害飘字 | 目标头顶飘出数字：白字普通 / 黄字暴击 / 绿字治疗 / 红字克制；上升 0.8s + 淡出，字体大小随伤害分级 |
| 血条 | 现有 BattleHealthBar 加**延迟扣血动画**（先白条后红条，经典 RPG 式） |
| 未命中/Miss | 头顶飘 "MISS" 灰字 + 音效 |
| 格挡/防御 | 蓝色 "GUARD" + 受击动画换成格挡姿势 |
| 屏幕反馈 | 大伤害震动 0.2s、暴击全屏闪白 0.05s、击杀慢动作 0.3s |
| 治疗 | 绿色粒子上升 + 数字飘字 |
| Buff 生效 | 角色头顶状态图标弹出（复用 BuffManager 数据），持续回合数角标 |

### 3.4 技能特效（P1，配表驱动）

**Luban skill 表加表现字段**（不动现有字段）：

```
fx_id        int     技能特效ID（Addressables 资源）
fx_scale     float   特效缩放
fx_offset    string  特效偏移 "x,y"
cast_anim    string  施法动画名（Spine，默认取技能名）
cast_sound   string  施法音效
hit_sound    string  命中音效
shake        int     屏幕震动强度 0-3
```

**特效分级**（按开发成本）：
- Lv1 纯逻辑反馈（飘字+闪白+血条动画）—— 所有技能先用这个保底
- Lv2 简单特效（圆形冲击波/粒子爆发/命中闪光）—— 每个技能配一个
- Lv3 定制演出（技能专属 Sequence 分支：特写、全屏效果、多段演出）—— 核心技能/大招专属

**特效资源管理**：走 Addressables（项目已在用），独立 AssetBundle 分组，不拖慢主场景加载。

### 3.5 行动表现序列（P0 核心，重写——参考憎恶之西的演出节奏）

> 憎恶之西的行动演出 = **喜剧三拍子：铺垫 → 夸张动作 → 延迟反应** + 大数字飘字。
> 精度不抠，节奏必须对。以下为 Hippo 细分时序（截图见 0.7 ①）。

#### 3.5.1 单目标完整时序

```
[0.00s] 锁定反馈：目标头顶 "!" 闪烁完成 → 行动者停顿 0.1s
[0.10s] 转身：行动者朝向目标（翻转 Sprite/Spine 朝向）
[0.15s] 走向目标：2D 位移 0.25s（SmoothStep 缓动）+ 走路动画 → 目标前 3/4 距离
[0.40s] 蓄力预备：夸张后仰 0.2s（喜剧铺垫，越夸张越好笑）
[0.60s] 出招冲刺：快速冲向目标 0.16s（位移 0.3）+ 攻击动画
[0.76s] 命中瞬间：全序列停顿 0.12s（打击感"敲定"）
[0.88s] 受击反馈：闪白 0.12s + 后仰位移 0.14s（Sin 曲线去+回）+ 受击动画
[1.02s] 喜剧延迟：再停顿 0.15s（让玩家看清"打中了"）
[1.17s] 伤害飘字：数字弹出（上升 0.8s 淡出，白/黄/绿/红/灰）
[1.20s] 血条延迟动画：白条残影 0.7s 缓动到实际 HP
[1.90s] 特效残留/粒子 0.5s（P1 配表驱动）
[2.40s] 归位：走回站位 0.25s
[2.65s] 下一位：高亮转移 + 回合横幅
```

总时长约 2.7s（单目标），多目标每多一个 +0.08s 反馈间隔。

#### 3.5.2 喜剧三拍子（憎恶之西风格，本序列的核心节奏）

| 拍子 | 表现 | 时序 |
|---|---|---|
| 铺垫 | 蓄力后仰 + 走向（玩家期待"要出招了"） | 0.15-0.60s |
| 夸张动作 | 冲刺出招（快速、幅度大、动画夸张） | 0.60-0.76s |
| 延迟反应 | 命中停顿 → 受击 → **再停顿 0.15s 才飘字** | 0.76-1.17s |

> 关键：**受击后不要立刻飘字**。先让受击动画演完，停顿一拍，再飘字——
> 这是 WoL"滑稽感"的来源，也是"伤害有存在感"的关键。

#### 3.5.3 多目标（AOE/行/列）处理

- 目标按格子顺序（左上→右下）依次反馈，每目标间隔 0.08s
- 飘字各自独立（并行上升），血条动画各自独立
- 出招动作只做一次（冲最近目标），其余目标只做受击反馈

#### 3.5.4 死亡演出（憎恶之西风格）

```
受击致死 → 先正常受击反馈 → 停顿 0.2s（喜剧延迟，像"诶？"）
→ 后仰倒下 0.45s（旋转 85° + 下移 0.25，翻白眼动画）
→ 纸片化淡出 0.3s（河马风格：可选喷水/变纸片飘走/炸成碎片）
→ 清除单位（显示层）
```

- `BattlePresenter.DeathRoutine` 已实现基础版（倒下+隐藏），P1 扩展纸片化/碎片
- 死亡判定后 0.2s 再演，避免与受击反馈重叠

#### 3.5.5 战斗叙述文本（WoL"文字即演出"，轻量版）

- 每次行动在顶部战斗文本区（或日志区首行）追加一行**打字机效果**叙述：
  - "河马使用 铁头功！" → "命中 土匪，造成 12 点伤害。"
  - "土匪 倒下了！"
- 口吻参考 WoL（戏谑、简洁、结果导向）
- 与 BattleLogPanel 同步，不新增喊话系统（喊话【暂缓】）

#### 3.5.6 跳过/加速

- 演出中点击/长按：2 倍速 → 再长按：4 倍速 → 直接跳过（进度条提示）
- 战斗设置开关：默认开，可关（首通建议关）

#### 3.5.7 实现结构

- `BattlePresenter.SkillSequenceRoutine` 已实现（2026-08-06 对齐时间轴）：停顿→转身→走向→蓄力预备（压扁拉伸）→出招冲刺→命中停顿→受击（闪白+后仰）→**喜剧延迟 0.15s**→飘字+白条残影→归位 全链路
- 时长常量集中定义（StartPause/FaceDuration/WindUpDuration/ComedyDelay...），后续迁到 SequenceConfig 配表
- 表现层只订阅事件，不侵入 BattleManager 逻辑（技能结算在前，演出在后）
- 附加：演出中点击加速（1→2.5→8 倍）、多目标按槽位排序依次反馈、死亡演出（旋转倒下+隐藏）已实现
- 动态选择（3.2）轻量版已实现：目标选择支持方向键/WASD 游标切换 + 回车确认 + Esc 取消（BattleWindow）
- 待补：死亡纸片化淡出、敌人出招预告（3.2.6，P1）、范围预览覆盖层（3.2.5，P1）

## 六、风险与注意

1. **别动逻辑层**：BattleManager 现有流程已验证，表现层只订阅事件，避免回归
2. **演出时长可控**：所有时长配表，默认 ≤5s/回合演出，可跳过
3. **特效性能**：2D 粒子 + Spine，注意 Addressables 加载时机（预加载当前战斗用特效）
4. **手机端**：Hippo 若上移动端，飘字/特效量要降级（可加 quality 开关）
5. **先 P0 后 P1**：P0 做完已有"像样回合制"的观感，P1 是锦上添花

## 七、一句话总结

> **给 Hippo 的战斗加一个"导演"：BattlePresenter 订阅逻辑事件，按 Sequence 剧本编排演出——选中反馈（九宫格预览/目标箭头/高亮）先行，飘字/受击/血条动画跟上，特效配表驱动，最后接上胜利结算闭环。采用演出序列+事件队列的通用架构，但不引入过度复杂度，按 Hippo 九宫格+Spine+Addressables 的现状做轻量实现。**
